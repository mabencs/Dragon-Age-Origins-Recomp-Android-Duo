# Signing

Two keys sign this project's APKs:

- **The shared debug key**, committed as [`app/debug.keystore`](../app/debug.keystore).
  Every debug build (`dev.daorecompandroid.duo`) is signed with it, on every machine, so
  a build from any computer installs over the last one.
- **Your own release key**, never in the repository. Release builds
  (`prod.daorecompandroid.duo`) are signed with it, and never with the debug key.

A release APK holds none of the game - the app makes the game's program on the player's
device (PLAN Phase 12) - so it is the one that is published, once `tools/release.py`
passes it (§5). A debug build stays on the developer's own devices: it is signed with a
public key, and `tools/push_gamecode.py` puts the developer's own build of the game's
program beside it.

---

## 1. Why the debug key is shared

Android lets an APK replace an installed app only if both are signed with the same key.
The Android Gradle Plugin signs debug builds with `~/.android/debug.keystore`, and if
that file does not exist it **generates a new one silently** on the first build. So
every machine used to have its own key, and a build from a second machine fails to
install over the first machine's:

```
INSTALL_FAILED_UPDATE_INCOMPATIBLE: Existing package dev.daorecompandroid.duo signatures do
not match newer version; ignoring!
```

The only way past that on the device is to uninstall the app, which **deletes its
storage**: the 6.4 GiB extracted game, the installed DLC, the title update and
`Lossless.dll` copied into it, the mods, and **the saves**. Sharing one key avoids that
permanently.

## 3. On a new machine

`python tools/bootstrap.py` copies the key to `~/.android/debug.keystore` when there is
none, and stops before Gradle when a different one is there. By hand, **before any
Gradle build**:

```powershell
# Windows
New-Item -ItemType Directory -Force "$env:USERPROFILE\.android" | Out-Null
Copy-Item app\debug.keystore "$env:USERPROFILE\.android\debug.keystore" -Force
```

```bash
# Linux / macOS
mkdir -p ~/.android && cp app/debug.keystore ~/.android/debug.keystore
```

If a `debug.keystore` is already there, an earlier build generated it: keep it elsewhere
if anything else uses it, and replace it. Then check the fingerprint matches §2:

```bash
keytool -list -v -keystore ~/.android/debug.keystore -storepass android | grep SHA256
```

### If you already built with a different key

Replace the keystore as above, then delete the stale APK so Gradle re-signs it rather
than reporting the package task up to date:

```bash
rm -rf app/build/outputs/apk/debug
./gradlew :app:assembleDebug
```

Confirm what the APK is signed with (it must print the SHA-256 in §2):

```bash
"$ANDROID_HOME/build-tools/36.1.0/apksigner" verify --print-certs app/build/outputs/apk/debug/app-debug.apk
```

## 4. If the device has the app under a different key anyway

Uninstalling is the only route, and it costs the app's storage. **Export the saves
first** (the launcher's *Saves - export, import, restore*, then *Export all saves*: a
.zip in `Download/Dragon Age Origins/`). Then:

1. `adb uninstall dev.daorecompandroid.duo`
2. Build with the shared key and install it.
3. In the launcher, choose the disc image, the title update, disc 2 and `Lossless.dll`
   again (README, "Setting up on the device"); the extraction takes about 8 minutes.
4. *Saves - export, import, restore*, then *Import saves from a .zip*.

## 5. Release builds and your own key

A release build is signed with a key of your own, which `app/build.gradle.kts` reads from
`~/.android/dao-release.properties` (or the file `-Pwarden.releaseSigning=<file>` names).
Without that file, a release build is left unsigned and the build says so. Make the key
once:

```bash
keytool -genkeypair -v -keystore ~/.android/dao-release.jks -alias dao-release \
    -keyalg RSA -keysize 4096 -validity 10950
```

and write `~/.android/dao-release.properties` beside it (`storeFile` is relative to the
properties file):

```properties
storeFile=dao-release.jks
storePassword=<the store password you chose>
keyAlias=dao-release
keyPassword=<the key password you chose>
```

**Back both files up.** A release signed with another key cannot install over one signed
with this key; losing it means uninstalling (§4) to update.

Then:

```bash
./gradlew :app:assembleRelease     # app/build/outputs/apk/release/app-release.apk
python tools/release.py            # checks it, keeps it in build/releases/<version>/
```

`tools/release.py` fails a release that is unsigned or signed with the debug key, or
that holds game files, the game's code (`libdaogame.so` or any of its functions),
`Lossless.dll`, or a path of the build machine, and one without what the device makes
the game's code with. It keeps the APK and the unstripped native library with its build
id, so a crash report from that release can be read later (`docs/TESTING.md`, "A release
build"). Publish only an APK it passed, built from a committed tree (About this app shows
the commit, with "+changes" when there were uncommitted ones).

A release build is a **separate app** from a debug build (`prod.daorecompandroid.duo`
against `dev.daorecompandroid.duo`). The two install side by side, and each has its own
game data, mods and saves: set the release up from the launcher like a new install, and
move saves across with the Saves page's export and import. The version comes from
`gradle.properties` (`warden.version`, `warden.releaseName`), and the version code from
the version's numbers, so a later release always installs over an earlier one.

## 6. Security

The debug key is in a public repository: anyone can sign an APK that Android accepts as
an update to a debug build of `dev.daorecompandroid.duo`. That is the nature of AGP's
standard debug key, and why **only APKs you built yourself** belong on your device. Use
the debug key for development builds only, and never to sign anything that leaves your
own devices.
